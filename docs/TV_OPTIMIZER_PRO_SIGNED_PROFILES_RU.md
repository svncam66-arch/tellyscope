# TV Optimizer Pro — управление доверенными профилями

**Статус:** разработана инфраструктура; производственный доверенный ключ отсутствует, аппаратная верификация Xiaomi №34 не выполнена. НИ ОДИН профиль пока не может получить реальный статус «Проверено».

## Модель доверия

1. Пользователь выбирает ровно два файла: JSON-манифест и его отдельную цифровую подпись `.sig`. Приложение НЕ делает их доверенными только потому, что они опубликованы на GitHub.
2. Приложение принимает только RSA-ключ владельца проекта, предварительно встроенный в APK как публичный ключ `app/src/main/assets/owner_profile_public_key.base64`. Если файла нет, все импорты отклоняются.
3. Подписываются **исходные байты JSON**, а не переупорядоченные/пересобранные JSON-поля.
4. Проверяются схема, версия, точная модель, API, полный fingerprint прошивки, утверждение владельцем, отметка реальных испытаний, минимум два HTTPS-источника на независимых хостах и отдельная инструкция восстановления для каждого разрешённого действия.
5. Пока единственный допустимый вид профильного действия — `disable` с обратным `enable`; команды терминала, удаление системных пакетов, перезагрузка и прошивка в подписанных JSON не поддерживаются.
6. Локальное хранилище перепроверяет подпись и fingerprint на каждом чтении; новый профиль должен иметь больший revision; есть отдельный ручной откат к предыдущей подписанной версии.
7. Даже полностью проверенный профиль НЕ может отменять отдельную защиту критических системных компонентов.

**Важно:** RSA-подпись доказывает авторство, но физическая безопасность действий требует документированного ручного тестирования и экспертной оценки. Поле `physical_tested` не следует заполнять `true` без реального испытания той же модели и прошивки.

## Пример схемы JSON (фиктивные значения для ознакомления)

```json
{
  "schema": 1,
  "id": "xiaomi-sample-NOT-VERIFIED",
  "revision": 1,
  "manufacturer": "Xiaomi",
  "model": "EXACT-MODEL",
  "sdk": 32,
  "build_fingerprint": "full/fingerprint/of/exact/firmware",
  "owner_approval": {
    "physical_tested": false,
    "tested_fingerprint": "full/fingerprint/of/exact/firmware",
    "review_id": "QA-NOT-APPROVED",
    "approved_at": 1,
    "independent_sources": [
      "https://github.com/verified-source/issues/1",
      "https://developer.android.com/"
    ]
  },
  "actions": [
    {
      "operation": "disable",
      "package": "com.example.sample",
      "recovery": "enable",
      "risk": "EXAMPLE ONLY. Do not disable without verifying dependencies.",
      "dependencies": []
    }
  ]
}
```

Этот пример **намеренно непригоден** для принятия: `physical_tested=false` и неподтверждённые параметры. Не использовать его как готовый профиль.

## Подпись профилей (только после экспертизы)

Ниже команды для машины владельца с установленным OpenSSL. **Закрытый ключ и пароль никогда не передавать в чат, GitHub или APK**. Бэкап закрытого ключа хранить в защищённом офлайн-хранилище отдельно от телефона.

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -aes-256-cbc -out tvop-owner-private.pem
openssl pkey -in tvop-owner-private.pem -pubout -outform DER | base64 | tr -d '\n' > owner_profile_public_key.base64
openssl dgst -sha256 -sign tvop-owner-private.pem -out verified-profile.json.sig verified-profile.json
```

Только публичную строку `owner_profile_public_key.base64` можно добавить в `app/src/main/assets/` перед сборкой. Менять ключ выпуска APK **не нужно**: подпись профилей и подпись APK — разные ключи и разные роли.

**Отдельно до stable:** протестировать генерацию профиля на конкретном Xiaomi, доставку подписанной базы GitHub с управляемыми версиями/rollback, проверки конфликта и зависимостей, защиту от несанкционированной подмены и полный журнал экспертизы.
