# TV Optimizer Pro — единое техническое задание
**Версия:** 0.1 (согласованное ТЗ, не свидетельство реализации)  
**Дата:** 2026-10-25  
**Исходный код:** https://github.com/svncam66-arch/tellyscope  
**Основа:** Tellyscope (GPL-3.0-only); все исходные уведомления об авторских правах и NOTICE сохраняются.

> Статус: требования согласованы по вопросам 1–33 и 35–52. Вопрос №34 — точные аппаратные модели/прошивки — ОТКРЫТ до получения сведений с реальных Xiaomi. До выполнения приёмки никакая APK не объявляется готовым стабильным продуктом. Наличие функции в ТЗ не означает, что она реализована в коде.

## 1. Назначение, платформы и выпуск
- **Название:** TV Optimizer Pro. Универсальный русскоязычный центр управления и оптимизации Android TV/Google TV; приоритет Xiaomi (№17, 33).
- **Контроллер:** Android 12+ (API 31+) на Huawei Mate X6, внешний и раскрытый экран, без обязательных Google Play Services (№5, 13, 51).
- **Тестовые цели:** Mi Box 2, Xiaomi TV Stick, Xiaomi TV. Их модель/SKU, Android и build fingerprint неизвестны; не считать устройства проверенными до испытаний (№24, 27, 34).
- **Лицензия/дистрибуция:** бесплатно через публичный GitHub Releases, соответствующий исходный код под GPL-3.0-only; сохранить атрибуцию Tellyscope, Kadb и прочих зависимостей (№50).
- **Первый стабильный выпуск** включает все обязательные функции этого ТЗ, без подмены заглушками (№26-А). Незавершённая/тестовая APK маркируется явно «экспериментальная, функционал неполон» и не является стабильным релизом.
- Приложение с **новым applicationId** и стабильной собственной подписью ставится рядом с экспериментальной старой APK; отсутствие автоматической миграции приватных данных следует честно сообщать (№25-Б, 31-В).
- **Избранный путь подписи:** ручная подпись стабильного APK одним защищённым локальным экземпляром keystore; ни ключ, ни пароль не размещаются в GitHub/исходниках/CI; риск потери единственного экземпляра принят (№43-А, 49-А). Подпись должна сохраняться между стабильными выпусками.
- Обновления: опциональная проверка GitHub Releases, уведомление и русские примечания; загрузка по явному согласию; перед установкой проверять SHA-256, подпись APK, ожидаемый package ID и совместимость versionCode/API, предупреждать о возможной миграции; Android-инсталляцию подтверждает пользователь (№25-Б).

## 2. Контроль устройств и ADB (№10, 15, 29, 35, 36, 38)
- Обнаружение в общей локальной сети Wi-Fi; ручной ввод IP, pairing-code на поддерживаемых устройствах, диагностика отказов, переподключение, несколько устройств. Нет обязательной поддержки режима хотспота или иных сетевых мостов (№38-А).
- Не пытаться «удалённо включить» выключенную в настройках устройства отладку ADB. Пользователю доступна пошаговая русская инструкция.
- Считать возможности устройства по модели, версии Android/прошивки и безопасным **только читающим** ADB-запросам; проверять разрешения; показывать «подтверждено / недоступно / неизвестно» и блокировать невозможные операции; повторять проверки при изменении прошивки/подключения (№36-Б).
- Каждая опасная операция — действие из **доверенного каталога команд**, с верификацией предикатов, предварительным просмотром и персональным подтверждением; нет свободного терминала ADB и произвольных скриптов (№29-Б).
- При обрыве ADB сохранять завершённость каждой операции, включая неизвестное состояние; не переисполнять опасные команды автоматически; после переподключения сверять фактическое состояние и предлагать продолжить/откатить/завершить.
- Запрет root, разблокировки загрузчика, изменения системных разделов, перепрошивки, отключения ключевых защит Android.

## 3. Каталог приложений, опасности и разрешённые действия (№1–3, 7, 9, 14, 19)
- Все изменяющие операции выбираются **вручную** галочками. Никаких предварительно отмеченных пакетов, скрытых массовых изменений или удаления без подтверждения.
- Показывать русское название, точный идентификатор пакета, установленную версию, производителя, назначение, зависимые компоненты, тип системного пакета, подтверждённость профиля, отдельные риски отключения и удаления, доступность отката.
- Поддержать доступные на данной прошивке stop/enable/disable, пользовательскую uninstall-for-user-0 и допустимое восстановление. Пользовательский uninstall не удаляет APK из системного раздела и не обещает возврат пользовательских данных.
- Неподтверждённые **некритические** системные пакеты допускают только ручное отключение с предупреждением и проверенным способом возврата; пользовательское удаление для них запрещено (№19-Б). Защищённые критические пакеты заблокированы в любых режимах.
- Проверять совместимость/зависимости/права до и после; групповые операции прерываются при серьёзной ошибке; отдельная история и контрольные точки, откат доступен лишь по фактическим техническим возможностям.
- Стандартные оптимизации и расширенный каталог экспертных операций (№14-В и 29-Б) с чёткими допустимыми командами, рисками, подтверждением, отменой или честным указанием её отсутствия.
- При неизвестной прошивке предлагать интеллектуальные **гипотезы** с градацией уверенности; не выдавать их за проверенные (№3-В).

## 4. Профили совместимости и экспертные рекомендации (№6, 17, 21, 24, 32, 40, 48)
- База профилей GitHub с локальным кэшем, версиями, превью изменений, ручным/опциональным обновлением, сравнением, импортом/экспортом и откатом базы при наличии предыдущей копии.
- Верифицировать источник, подпись/целостность, версию, происхождение и привязку к точной модели + прошивке; цифровая подпись подтверждает происхождение, **не истинность рекомендации**.
- Статус «Проверено» присваивается **только владельцем проекта** после документированных испытаний и сопоставления нескольких источников, в том числе сообщений сообщества (№32-Б, 48-А). Пользовательские списки не получают этот статус самостоятельно.
- При противоречии данных блокировать спорную операцию до повторной проверки (№40-Б), не блокируя безопасные несвязанные операции.
- Матрица статусов по каждому устройству: «Проверено», «Частично совместимо», «Не проверено». Нельзя распространять тесты одной прошивки на другую без доказательств.
- Данные профиля не могут отменять жёсткие локальные запреты на изменения критических системных пакетов.

## 5. Центр оптимизации, диагностика и лаборатория (№4, 8, 22, 45)
- Отображать доступные CPU, RAM, накопитель, температуру, сеть, процессы, историю, предупреждения. Если показатель недоступен по ADB — «нет данных», никогда не рисовать вымышленные значения.
- Стандартные тесты «до/после» при сопоставимых условиях; повторения, среднее и разброс; учитывать ограничения методики и прошивки; предупреждать о регрессиях, предлагать доступный откат.
- Русские технические **локальные текстовые отчёты** с безопасным обезличиванием секретов (№45-А), без обязательных графических/PDF-экспортов.
- Записывать дату, устройство, версию прошивки, произведённые операции, фактические измерения, погрешности и недоступные параметры.

## 6. Модули и русский интерфейс (№5, 11–13, 39, 47)
- Сохранить и улучшить из Tellyscope: подключение, список/состояние устройств, управление пакетами, деблоатинг с защитой, история, настройки, файловый менеджер, пульт, APK-установка, диагностика и оптимизация.
- Файлы: просмотр и передача телефон ↔ ТВ, создание каталогов, переименование, удаление **разрешённых пользовательских** файлов по подтверждению; без бесконтрольного доступа к защищённым данным (№47-Б).
- APK на ТВ: локальные файлы плюс загрузка из **предварительно проверенных GitHub Releases** по явному запросу с проверкой целостности, источника и ограничений Android (№52-Б). Обычные произвольные URL не предусмотрены.
- Русские тексты у **каждого собственного элемента UI**: заголовки, иконки accessibility, ошибки, системные инструкции, списки, предупреждения, изменения и сообщения. Имена/ID установленных сторонних пакетов остаются неизменными; латинские технические ID — по необходимости. Английские строки собственного интерфейса блокируют стабильный выпуск (№12-В).
- Брендинг: **TV Optimizer Pro**, самостоятельная иконка, лесной зелёный/золото. Личная эмблема «ИАА» только заставка/настройки/«О программе», не заменяет иконку продукта (№28-Б, 33-В). Сохранить лицензию/авторов.
- Продуманная компактная раскладка на внешнем экране Mate X6, многопанельный адаптивный режим на внутреннем, запоминание выбора, отсутствие обязательных Google-сервисов.

## 7. Конфиденциальность, резервные копии, офлайн (№16, 20, 23, 37, 41, 42)
- Основные операции подключённого ТВ работают без **интернета** через локальную Wi-Fi сеть с ранее загруженными профилями; GitHub нужен для новых версий и профилей; сетевые проверки отключаемы (№37-А). Не обещать работу ADB без самой локальной связи.
- Не выполнять автоматическую внешнюю телеметрию или облачную синхронизацию.
- Шифровать чувствительные локальные данные и ключи ADB; локальные резервные копии по настраиваемому графику, парольный экспорт/импорт, контроль целостности, выборочное восстановление и удаление данных.
- Экспорт ADB-ключей выключен по умолчанию; только отдельное подтверждение и **отдельный пароль**, ни при каких условиях не выдавать секреты в текстовых отчётах (№41-Б).
- История и журналы хранятся **без автоматического удаления по умолчанию**; обеспечить ручную очистку выбранных записей (№42-В).
- Центр восстановления сообщает доступность возврата до операции, проверяет состояние после перезагрузки, документирует частично необратимые последствия, предоставляет инструкцию ручного восстановления при отсутствии ADB.

## 8. QA и критерии стабильного релиза (№18, 24, 26, 30, 35, 44, 46)
- Первая стабильная версия содержит все обязательные функции настоящего ТЗ (№26-А). Статусы «заглушка», «не реализовано», «переведено частично» — не выполненные требования.
- QA на каждый модуль по техническим чек-листам; автоматические unit/integration, UI/локализация, безопасность/восстановление, разрывы ADB, перезагрузки, имитации и сборки (№18-В, 30-А).
- **Прямо сейчас** реальные испытания можно отложить и использовать mock/симуляцию ADB (№35-С). **До стабильного выпуска** необходимо реально испытать хотя бы одно Xiaomi; остальные остаются «не проверено» (№44-Б). Выбранное ограничение не разрешает ложно объявлять universal compatibility проверенной.
- Блокирующие дефекты: критические проблемы безопасности/данных/подключения и отсутствие обязательной функциональности (№46-А). Для русификации действует более строгий ранее согласованный барьер №12.
- Подписанные стабильные APK и обновления, совместимые друг с другом; отдельная миграция с предыдущей экспериментальной APK по №31. Тестовые APK чётко маркировать экспериментальными.
- **Никакого автоматического продакшен-релиза** из неполной рабочей ветки; контроль успешных тестов не равен завершению всего ТЗ.

## 10. Открытая информация (НЕ придумывать)
- **Вопрос №34:** реальные SKU, Android API, номер сборки и результаты безопасного capability probe для Mi Box 2, Xiaomi TV Stick, Xiaomi TV — выясняются перед физическими испытаниями.
- Идентификатор нового приложения и release versionCode фиксируются в исходниках до стабильного выпуска; смена стабильного applicationId в будущем означает отдельную установку.
- Специфика носителя личной эмблемы «ИАА» требует утверждённого исходного векторного/растрового ресурса для качественной и точной реализации; не подменять произвольным вариантом.

## 11. Правила ведения проекта
1. Ни один элемент матрицы не переводить в «готово», пока не доказаны критерии проверки.
2. В коммитах и release notes разделять **согласовано / реализовано / протестировано / подтверждено на реальном устройстве**.
3. Ключи, секреты, IP-адреса, личные сетевые идентификаторы не фиксировать в репозитории/логах.
4. Любая промежуточная APK не является стабильным TV Optimizer Pro и не заменяет старую установленную версию автоматически.
5. Вносить изменения с возможностью ревью; не публиковать в стабильном GitHub Release недоработанную сборку.
